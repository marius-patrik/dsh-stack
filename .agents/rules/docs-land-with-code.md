# Docs land with the code

New architecture-decision docs and PRD sections for a capability must land in the
same pull request as the code that introduces that capability. Documentation
describes what shipped, not what is planned.

A pull request that adds a capability without its doc update is incomplete, the
same way a pull request that adds a capability without tests is incomplete.
Planned or deferred work belongs in a linked GitHub issue, never in a doc written
as though it already exists.
